# 深度 FAQ

> 覆盖技术选型、架构设计、多 Agent 协同、边界情况判断等边缘场景的常见问题。
> 本文档按需加载，供高频用户深度参考。

## 技术选型相关

**Q1: 用户已有既定技术栈，还要走选型流程吗？**
A: 不需要。走"已有项目反向分析"（tech-stack-guide.md 第 6 节），只评估与优化，不重新选型。这是本 Skill 的最高频误用场景之一。

**Q2: 用户说"剩下的你帮我自动选择"，AI 能全权决定吗？**
A: 可以接受授权，但 AI 仍需逐次说明每个动态推荐，并让用户确认。授权不意味着可以跳过任何层级的展示与确认。

**Q3: 支持的工具没有 `ask_followup_question` 怎么办？**
A: 回退文字列表选型：在正文逐层列出候选（每项标注"推荐"+理由），用户回复编号或名称确认后继续。其余协议（动态调研、候选规则、选择权）不受影响。

**Q4: 同一层级多选后如何落地？**
A: 必须在 Core 层为每个方案独立封装，通过统一接口对外暴露，业务模块只调用 Core 接口。多选决策必须记录 ADR，说明各方案的职责分工和路由规则。

**Q5: 如何判断某层级是否可多选？**
A: 按 0.5 多选兼容评估协议：先做冲突检测（结构性冲突则互斥），再评估互补收益（无不可替代收益则单选）。多选是 AI 评估后的推荐，最终由用户决定。

## 架构设计相关

**Q6: S/M 级项目也需要 ADR 吗？**
A: 不需要。仅 L 级或高风险决策生成 ADR。S/M 级记录在 `.agent/architecture.md` 的技术栈清单即可，避免过度工程。

**Q7: Core 层什么时候允许修改？**
A: 任何修改必须说明：修改原因、影响范围、兼容方案、迁移方案。Core 的设计目标是"稳定、通用、低变化"，频繁修改是反模式。

**Q8: 前端模块可以直接 import 后端模块吗？**
A: 禁止。跨模块通信：后端走 Application Service 或事件驱动，前端走 Props/Events + Core Store 共享。模块间直接 import 组件需提升到 Core/ui。

**Q9: Monorepo 是必须的吗？**
A: 不是。仅当项目包含前端 + 后端 + 共享类型时考虑，且属于 L 级可选结构。小项目用 Monorepo 反而增加复杂度。

## 跨 Agent / 协作相关

**Q10: 换个 AI 会话/Agent 后如何保持上下文？**
A: 依赖 `.agent/` 四件套 + `docs/adr/`。新 Agent 必须先读 context.md（定位与背景）、architecture.md（架构与决策）、coding-rule.md（规范）、workflow.md（流程）。

**Q11: 多个 Agent 并行开发同一项目怎么分工？**
A: 按业务模块划分边界，通过 ADR 同步跨模块决策。每个 Agent 开发前先读 `.agent/` 文档，遵守"新增功能前检查 Core → 已有模块 → Plugins"的复用规则。

## 边界情况判断

**Q12: 用户需求介于 S 与 M 级之间怎么判定？**
A: 默认假设 M 级低风险，只有风险信号明确（支付、认证、敏感数据、外部用户、7x24、多人协作）才升级门禁。先展示判定结果和影响，再继续。

**Q13: 选型到一半用户改主意（如 Vue 换 React）？**
A: 走 7.5 变更流程：评估影响范围（受影响的后续层级 + 将失效的方案）→ 提示用户确认 → 重新执行受影响层级（含动态调研）→ 更新进度与汇总。

**Q14: 用户自定义了不兼容的技术（如 Svelte 用 Element Plus）？**
A: 不拒绝用户选择，但必须提示兼容性风险并提供替代方案；无法判断兼容性时标注"未知兼容性，请用户自行验证"。最终决定权归用户。

**Q15: 纯前端项目还要选数据库吗？**
A: 不需要。被跳过的端不逐层勾选，直接在选型结果汇总中标注"本项目不需要"。

## 异常恢复与故障处理

**Q16: 选型到一半 AI 报错中断了，怎么继续？**
A: 重新打开会话后，AI 会自动检测 `.agent/selection-progress.md`（M 级及以上每轮自动保存）。检测到未完成进度时提示"已完成 X/Y，是否继续？"，选"继续"即从断点恢复，不用从头重选。S 级无此文件则重新开始。已完成的技术栈汇总存在 `.agent/architecture.md`，新会话的 AI 会先读这两个文件恢复上下文。

**Q17: `web_search` 查询版本一直超时怎么办？**
A: AI 会自动回退到 `tech-stack-guide.md` 内置版本基线，标注"版本可能滞后，请复核"。选型流程不会因此中断。你也可以手动告诉 AI 具体版本号跳过查询。

**Q18: 依赖安装一直失败怎么处理？**
A: AI 会依次尝试：①切换国内镜像源（npm→npmmirror、pip→清华源）②检查 Node/Python 版本是否匹配 ③清缓存重试。连续失败 3 次暂停，保留完整诊断输出请你介入，不会反复盲目重试。

**Q19: 国内网络环境 Git clone 很慢怎么办？**
A: 使用代理加速：`ghproxy.com`（GitHub 代理）或 `gitclone.com`（镜像站）。SKILL.md"环境与工具适配"表已列出此回退方案，AI 会主动提示。

## 边界场景与演进相关

**Q20: 项目从 S 级演变成 L 级（脚本变成正式产品），怎么升级架构？**
A: 走"补门禁流程"：①告知用户当前为 S 级，目标为 L 级，列出需补齐的产物（`.agent/` 四件套、`docs/adr/`、Core + DDD 模块、CI/安全/发布门禁）②已生成的代码不重写，仅补缺漏的产物 ③新功能按 L 级门禁执行 ④写入 `.agent/architecture.md` 的"演进记录"小节。禁止一次性推翻重写。

**Q21: 项目从 L 级降级到 M 级（团队解散、项目归档），怎么处理？**
A: 不强制拆除已有架构。标记当前级别为"维持现状 + 降级目标"，新功能按 M 级门禁执行，旧的 L 级产物（ADR、Core 模块）作为历史记录保留。归档场景可在 README 顶部加"已归档"标记。

**Q22: 用户模式可以切换吗？比如从引导模式切到专家模式。**
A: 可以。用户主动声明即可（如"我现在懂了，剩下的让我自己选"）。切换后选型流程不变，AI 把"推荐项 + 解释"输出密度调整为"候选清单"，不推翻已选清单，从下一轮开始按新模式进行。

**Q23: 选型完成后想新增一个之前没选的层级（如引入 Redis、RabbitMQ、消息队列）怎么走？**
A: 走"补选流程"：①确认是新增层级还是替换已选方案 ②如为新增层级，单独走该层级选型协议（动态调研 + 候选 + 用户确认）③更新 `.agent/architecture.md`，L 级补 ADR ④禁止静默引入未走选型协议的依赖到代码库。

**Q24: 多个 AI Agent 并行开发同一项目，怎么避免技术栈冲突？**
A: ①并行选型禁止——技术栈必须由唯一主 Agent 决定，其他 Agent 走"反向分析 + 只读模式"②开发阶段按业务模块划分边界，每个 Agent 负责独立模块 ③Core 层只允许主 Agent 修改，其他 Agent 通过 ADR 提议变更 ④进度文件并发访问见 7.6 多 Agent 并发处理（加锁 + 僵尸锁覆盖 + 主动询问用户）。

**Q25: 跨项目想复用同一套技术栈配置，怎么办？**
A: 把技术栈汇总提取到独立的 `tech-stack-profile.md`，作为新项目的预设基线。新项目仍走完整选型流程，但可"基于预设 + 增量差异"模式加速——预设层级标注"沿用预设"，仅增量层级走动态调研 + 用户确认，不跳过用户决策。

**Q26: 国内项目上线必须 ICP 备案吗？涉及数据出境怎么办？**
A: ①部署在国内的服务必须使用已 ICP 备案域名（管局备案），未备案域名国内访问不通 ②用户数据原则上不出境，跨境传输需走安全评估 ③涉及等保 2.0 的项目应在 L 级门禁中体现 ④本 Skill 仅做提示，不替代合规咨询，由用户自行确认法律边界。

**Q27: 进度文件 `.agent/selection-progress.md` 损坏了怎么办？**
A: 见 7.6"工具报错恢复"表的"进度文件损坏"行：①尝试用已选清单+时间戳片段恢复可识别部分 ②询问用户"是否保留已选 X 项继续？还是从头开始" ③若用户选择保留，把可用项重写为规范格式。禁止静默清空或忽略损坏文件。

**Q28: AI 误跳过了一个选型层级（如忘了问 CSS 方案），怎么补救？**
A: 立即补问被跳过的层级，标注"⚠️ 上轮漏选层级补问"，不强制推翻后续已选。如后续已选方案与漏选层级冲突（如漏选了 CSS 方案，已选了 UI 组件库且需要特定 CSS 框架配合），按 7.5 变更流程处理。

**Q29: 项目演进入口在哪？已选型项目想升级架构、引入新理念怎么办？**
A: 走"反向分析 + 选型差异"流程：①先用反向分析评估现状，列出差距清单 ②按差距逐项走选型变更流程 ③禁止整体推翻重选 ④写入 `.agent/architecture.md` 的"演进记录"小节，包含时间、触发原因、变更清单、影响范围。

**Q30: 引入 AI 模型 API 时如何保证跨平台兼容（境外 + 国产）？**
A: 境外模型（OpenAI/Anthropic/Google）与国产模型（DeepSeek/智谱 GLM/通义千问/文心/Kimi）必须在选型时同时列出，由用户决定。落地时通过 Core 层抽象统一接口（如 `core/llm/provider.ts` + 各厂商 adapter），禁止业务层直接 import 特定厂商 SDK。多模型场景需 ADR 说明路由规则与降级策略。
