# 深度 FAQ

> 覆盖技术选型、架构设计、多 Agent 协同、边界情况判断等边缘场景的常见问题。
> 本文档按需加载，供高频用户深度参考。

## 技术选型相关

**Q1: 用户已有既定技术栈，还要走选型流程吗？**
A: 不需要。走"已有项目反向分析"（tech-stack-guide.md 第 6 节），只评估与优化，不重新选型。这是本 Skill 的最高频误用场景之一。

**Q2: 用户说"剩下的你帮我自动选择"，AI 能全权决定吗？**
A: 可以接受授权，但 AI 仍需逐次说明每个动态推荐，并让用户确认。授权不意味着可以跳过任何层级的展示与确认。

**Q3: 支持的工具没有 `ask_followup_question` 怎么办？**
A: 回退文字列表选型：在正文逐层列出候选（每项标注"推荐"+理由），用户回复编号或名称确认后继续。其余协议（动态调研、候选规则、选择权）不受影响。

**Q4: 同一层级多选后如何落地？**
A: 必须在 Core 层为每个方案独立封装，通过统一接口对外暴露，业务模块只调用 Core 接口。多选决策必须记录 ADR，说明各方案的职责分工和路由规则。

**Q5: 如何判断某层级是否可多选？**
A: 按 0.5 多选兼容评估协议：先做冲突检测（结构性冲突则互斥），再评估互补收益（无不可替代收益则单选）。多选是 AI 评估后的推荐，最终由用户决定。

## 架构设计相关

**Q6: S/M 级项目也需要 ADR 吗？**
A: 不需要。仅 L 级或高风险决策生成 ADR。S/M 级记录在 `.agent/architecture.md` 的技术栈清单即可，避免过度工程。

**Q7: Core 层什么时候允许修改？**
A: 任何修改必须说明：修改原因、影响范围、兼容方案、迁移方案。Core 的设计目标是"稳定、通用、低变化"，频繁修改是反模式。

**Q8: 前端模块可以直接 import 后端模块吗？**
A: 禁止。跨模块通信：后端走 Application Service 或事件驱动，前端走 Props/Events + Core Store 共享。模块间直接 import 组件需提升到 Core/ui。

**Q9: Monorepo 是必须的吗？**
A: 不是。仅当项目包含前端 + 后端 + 共享类型时考虑，且属于 L 级可选结构。小项目用 Monorepo 反而增加复杂度。

## 跨 Agent / 协作相关

**Q10: 换个 AI 会话/Agent 后如何保持上下文？**
A: 依赖 `.agent/` 四件套 + `docs/adr/`。新 Agent 必须先读 context.md（定位与背景）、architecture.md（架构与决策）、coding-rule.md（规范）、workflow.md（流程）。

**Q11: 多个 Agent 并行开发同一项目怎么分工？**
A: 按业务模块划分边界，通过 ADR 同步跨模块决策。每个 Agent 开发前先读 `.agent/` 文档，遵守"新增功能前检查 Core → 已有模块 → Plugins"的复用规则。

## 边界情况判断

**Q12: 用户需求介于 S 与 M 级之间怎么判定？**
A: 默认假设 M 级低风险，只有风险信号明确（支付、认证、敏感数据、外部用户、7x24、多人协作）才升级门禁。先展示判定结果和影响，再继续。

**Q13: 选型到一半用户改主意（如 Vue 换 React）？**
A: 走 7.5 变更流程：评估影响范围（受影响的后续层级 + 将失效的方案）→ 提示用户确认 → 重新执行受影响层级（含动态调研）→ 更新进度与汇总。

**Q14: 用户自定义了不兼容的技术（如 Svelte 用 Element Plus）？**
A: 不拒绝用户选择，但必须提示兼容性风险并提供替代方案；无法判断兼容性时标注"未知兼容性，请用户自行验证"。最终决定权归用户。

**Q15: 纯前端项目还要选数据库吗？**
A: 不需要。被跳过的端不逐层勾选，直接在选型结果汇总中标注"本项目不需要"。

## 异常恢复与故障处理

**Q16: 选型到一半 AI 报错中断了，怎么继续？**
A: 重新打开会话后，AI 会自动检测 `.agent/selection-progress.md`（M 级及以上每轮自动保存）。检测到未完成进度时提示"已完成 X/Y，是否继续？"，选"继续"即从断点恢复，不用从头重选。S 级无此文件则重新开始。已完成的技术栈汇总存在 `.agent/architecture.md`，新会话的 AI 会先读这两个文件恢复上下文。

**Q17: `web_search` 查询版本一直超时怎么办？**
A: AI 会自动回退到 `tech-stack-guide.md` 内置版本基线，标注"版本可能滞后，请复核"。选型流程不会因此中断。你也可以手动告诉 AI 具体版本号跳过查询。

**Q18: 依赖安装一直失败怎么处理？**
A: AI 会依次尝试：①切换国内镜像源（npm→npmmirror、pip→清华源）②检查 Node/Python 版本是否匹配 ③清缓存重试。连续失败 3 次暂停，保留完整诊断输出请你介入，不会反复盲目重试。

**Q19: 国内网络环境 Git clone 很慢怎么办？**
A: 使用代理加速：`ghproxy.com`（GitHub 代理）或 `gitclone.com`（镜像站）。SKILL.md"环境与工具适配"表已列出此回退方案，AI 会主动提示。
