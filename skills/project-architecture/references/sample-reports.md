## 样例 1：领域模型草图（产品模式，需求分析阶段）

**场景：** 宠物寄养小程序，用户提供 PRD 后由 AI 生成的领域模型草图。

```markdown
## 领域模型草图

### 1. 核心领域

| 领域 | 描述 | 优先级 |
|------|------|--------|
| 订单 | 寄养服务的预订与支付全流程 | P0 |
| 寄养 | 寄养店/寄养师的服务能力管理 | P0 |
| 宠物档案 | 宠物信息与健康要求 | P1 |
| 评价 | 服务完成后的互评体系 | P2 |

### 2. 实体与关系

| 实体 | 关键属性 | 关联实体 | 关系类型 |
|------|----------|----------|----------|
| 用户 | id、手机号、昵称 | 宠物（拥有） | 一对多 |
| 宠物 | id、品种、年龄、疫苗状态 | 订单（被寄养） | 一对多 |
| 寄养店 | id、名称、容量、资质 | 订单（承接） | 一对多 |
| 订单 | id、时段、价格、状态 | 用户/宠物/寄养店 | 多对一 |

### 3. 核心业务流程

流程1: 下单预订
1. 用户选择寄养店与时段
2. 系统校验容量与资质
3. 生成待支付订单
4. 支付成功 → 订单生效并锁定容量
5. 寄养开始/结束 → 更新订单状态

流程2: 服务评价
1. 订单完成后 7 天内可评价
2. 用户评价寄养店，寄养店可回复
3. 评价影响店铺评分

### 4. 业务边界
- **包含：** 预订、支付、评价、寄养状态跟踪
- **不包含：** 宠物医疗、保险理赔、实时视频监控

### 5. 非功能性需求
| 维度 | 要求 |
|------|------|
| 并发量 | 日均 1,000 单，峰值 QPS 50 |
| 数据量 | 年订单量 10 万级 |
| 响应时间 | 下单接口 < 500ms |
| 可用性 | 支付环节需 99.9% |
```

## 样例 3：已有项目反向分析报告

**场景：** 用户提供一个 Vue 2 + Express 的遗留仓库，AI 输出反向分析报告。

```markdown
## 项目反向分析报告

### 1. 项目概况
- 项目名：运营中台（示例）
- 规模级别：L（多模块、团队协作、长期维护）
- 当前阶段：稳定维护期

### 2. 技术栈画像
| 层 | 选型 | 版本 | 最新版本 | 状态 |
|----|------|------|----------|------|
| 前端-主框架 | Vue | 2.7.x | 3.5.x | ⚠️ 过时 |
| 前端-构建 | Webpack | 5.x | 5.x（迁移至 Vite） | ⚠️ 建议迁移 |
| 后端-框架 | Express | 4.x | 5.x | ⚠️ 过时 |
| 后端-数据库 | MySQL | 5.7 | 8.x | ⚠️ 过时 |

### 3. 架构评估
- 架构模式：分层（controller/service），无 DDD 边界
- 目录规范度：⚠️ 部分（无 core/ 与 modules/ 划分）
- Core 层完整度：❌ 无公共能力封装，各模块直连 axios
- 模块化程度：⚠️ 服务层混放业务规则

### 4. 代码质量评估
- 代码质量工具：❌ 无 ESLint/Prettier 配置
- 测试覆盖：❌ 无测试目录
- 安全实践：⚠️ 存在硬编码密钥 2 处

### 5. 问题清单
| # | 问题 | 严重度 | 建议方案 |
|---|------|--------|----------|
| 1 | Vue 2 已停止维护 | 高 | 迁移至 Vue 3 + Vite |
| 2 | 无公共能力封装 | 高 | 建立 core/ 层（http/auth/utils） |
| 3 | 硬编码密钥 | 高 | 迁移至环境变量 + 密钥管理 |
| 4 | 无测试与 Lint | 中 | 引入 Vitest + ESLint |

### 6. 优化建议（按优先级排序）
1. **P0**：迁移密钥至环境变量，修复硬编码
2. **P0**：建立 core/ 层，收敛重复封装
3. **P1**：升级 Vue 3 + Vite（评估兼容性后分批迁移）
4. **P2**：补充单元测试与 CI 门禁
```
