# 开发工作流（.agent/workflow.md）

> 本文件定义项目开发、验证、发布与回滚流程。命令和环境必须按项目实际填写，不得保留未确认的占位配置。

## 项目门禁

| 项目规模 | 风险等级 | 必需门禁 | 负责人 |
|----------|----------|----------|--------|
| S / M / L | 低 / 中 / 高 |  |  |

高风险项目至少启用安全扫描、备份恢复和发布回滚门禁；被裁剪的门禁必须记录原因。

## 分支策略

- 主分支：`main`
- 功能分支：`feature/<scope>-<desc>`
- 修复分支：`fix/<issue>-<desc>`
- 合入方式：PR/MR + 至少 1 人 review（个人项目可自审）
- 生产发布只能从已验证的提交或受保护标签执行

## Commit 规范

Conventional Commits：`feat(order): 支持订单取消原因备注`

type: `feat` | `fix` | `refactor` | `docs` | `test` | `chore` | `perf` | `style`

- 一个 commit 只做一件事
- subject 使用祈使句，长度不超过 72 个字符
- 破坏性变更在 footer 标注 `BREAKING CHANGE:`

## 需求就绪检查（Definition of Ready）

开始实现前确认：

- [ ] 用户问题、目标和非目标已明确
- [ ] 核心用户流程和验收标准已确认
- [ ] 领域边界、数据变更和权限影响已评估
- [ ] 依赖、风险和未决问题已有负责人
- [ ] 规模与风险等级已评估
- [ ] 需要新增或修改的架构决策已识别

## 新功能开发流程

1. 阅读 `README.md`、`.agent/` 文档、相关模块和依赖配置
2. 检查 Core、已有模块和 Plugins，优先复用
3. 输出修改、新增、删除文件清单及影响范围
4. 在对应模块内实现，遵守分层和依赖方向
5. 对外接口、数据库迁移、权限和错误处理同步设计
6. 补充单元、集成和核心流程测试
7. 执行本地验证与安全检查
8. 提交 PR，描述改动、风险、迁移和回滚方式
9. 根据 review 反馈修改，并更新架构文档或 ADR

## Definition of Done

- [ ] 功能满足验收标准，异常和边界场景已处理
- [ ] 测试已补充并通过
- [ ] Lint、类型检查和构建通过
- [ ] 外部输入已验证，权限已校验，日志已脱敏
- [ ] 依赖、配置、迁移和文档已同步
- [ ] 未引入未说明的依赖、密钥或无关重构
- [ ] PR review 已完成，变更摘要和风险已记录

## 本地验证命令

```bash
# 按项目实际填写；不适用项明确写 None (not needed)
<lint-command>
<typecheck-command>
<unit-test-command>
<integration-test-command>
<e2e-test-command>

```

验证顺序：Lint → Type Check → Unit/Integration Test → E2E（核心流程）→ Build。
任何失败都必须修复或记录为明确阻塞项，不得以“本地可运行”替代验证。

## CI 安全门禁

- [ ] 依赖漏洞扫描
- [ ] 密钥扫描
- [ ] SAST / 代码质量扫描
- [ ] 容器镜像与 IaC 扫描（适用时）
- [ ] 许可证合规检查
- [ ] 测试、类型检查和构建通过
- [ ] 制品可追溯到提交、版本和构建日志

高风险项目禁止绕过失败的安全门禁；例外必须由负责人批准并记录期限、风险和补救计划。

## 数据库与配置变更

- [ ] 迁移脚本可重复执行或具备幂等保护
- [ ] 已验证向前迁移和回滚/补偿方案
- [ ] 生产迁移前完成备份并确认恢复点
- [ ] 破坏性变更采用 expand → migrate → contract 分阶段策略
- [ ] 配置和密钥通过环境变量或密钥管理系统注入

## 发布流程

### 发布前

- [ ] 验收标准全部满足
- [ ] CI 全部通过，制品已生成并校验
- [ ] 发布版本、变更日志和影响范围已确认
- [ ] 数据库迁移、备份、回滚条件和负责人已确认
- [ ] 监控、告警、日志和健康检查已就绪
- [ ] 灰度/分批发布策略已确认（适用时）

### 发布执行

1. 创建版本：`<version-command>`
2. 发布制品：`<artifact-release-command>`
3. 执行数据库迁移：`<migration-command>`
4. 按环境顺序发布：`<environment-order>`
5. 执行健康检查和核心流程冒烟测试
6. 观察错误率、延迟、资源和业务指标：`<observation-window>`

### 回滚流程

触发条件：错误率、核心业务失败率、延迟、数据一致性或安全指标超过既定阈值。

1. 冻结继续发布并记录事件
2. 回滚应用制品：`<rollback-artifact-command>`
3. 按已验证方案处理数据库迁移，禁止盲目回滚破坏性迁移
4. 验证健康检查、核心流程和数据一致性
5. 通知相关人员并记录事故、原因和后续行动

## 发布后检查

- [ ] 发布版本与运行实例一致
- [ ] 健康检查、关键接口和核心业务流程通过
- [ ] 监控与告警无异常
- [ ] 数据库迁移结果已确认
- [ ] 发布记录、变更日志和 ADR 已更新
- [ ] 观察窗口结束后完成发布结论

## 架构决策与变更记录

涉及技术栈、公共 Core、数据模型、接口兼容性、部署、安全或迁移的决策，新增 `docs/adr/NNN-<title>.md`，并同步更新 `.agent/architecture.md`。
